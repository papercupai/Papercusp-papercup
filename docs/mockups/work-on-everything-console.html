    How these concepts fit the existing goal
    Dedicated destination

    The special entry opens this workspace view. Show goal health, work coverage, priorities, decisions, verified outcomes, and spend first. Keep the steward conversation one click away.

    Reuse the current model

    Use the existing goal detail and ongoing-work model for status, priorities, plans, attention, and outcomes. Worklist ordering and exclusions map to the goal’s existing worklist policy. Do not show a completion percentage for this standing goal.

    Implementation path

    Reuse registered controls, rich grid, banners, and dialogs. Store view and selection in the URL with nuqs; read through the existing sync layer. Budget windows remain explicit. This offline gallery makes no API calls.

    What the worklist iterations (02A–02C) change, and what each needs from the product
    02A · Priority tiers

    Ranks 1–6 suggest a precision the steward does not use. Three tiers match how allocation works: fill Focus, then Next, then spare capacity. Order inside a tier is only a tiebreak. Excluded plans leave the ranking, and new plans wait for a decision.

    Needs: a coarse priority (tier) in the goal’s worklist policy alongside ordering and exclusions. Drag-to-reorder is not in the component registry yet; rows use data.rich-grid, and a control.select “Move to” menu covers keyboard and touch.

    02B · Capacity steering

    Order decides who goes first; a share decides how much. Showing agents as blocks makes allocation visible, and every limit is explained: ready work, a blocker, or the budget.

    Needs: a per-plan share in the worklist policy, plus a dry-run from the steward’s allocator. A segmented control is not registered; use control.select or register one. Risk: more knobs invite micromanagement, so this works best as an advanced mode.

    02C · Draft & apply

    Priority edits move agents, so they are staged. The steward estimates the effect before anything changes, and each change can keep a reason that the steward reads too.

    Needs: a history of worklist-policy changes (check whether the goal model already records one) and the same allocator dry-run. Uses overlay.modal for review. The list is keyboard-first, with visible controls on narrow screens.

    Suggested combination: use 02A as the base, open 02C’s draft bar whenever a change would move agents, and keep 02B’s agent strip as a read-only “where agents are” summary above the tiers.

    Try switching concepts, opening a plan, changing scope, pausing the goal, or reviewing a decision. In 02A–02C, drag between tiers, change a share, or reorder with the keyboard.All figures and activity are illustrative.

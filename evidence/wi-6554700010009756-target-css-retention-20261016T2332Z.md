## Source correlation and conclusion

`systemd-scope.ts` emits `--collect` plus `CollectMode=inactive-or-failed` by default. Task-manager callers pass `collectFailedUnit:false` so terminal properties are persisted before a failed unit is reset. The task manager and reconciler use the systemd-backed release probe; inactive, failed, or unknown units count as released, while a degraded scan remains report-only.

The current evidence supports deferred kernel CSS teardown after systemd unit release. It does not identify an application-held pin: the pending CSSs had no live systemd unit, process, or cgroup control group, and other CSSs with positive offline refcounts freed within the same window. No repository code fix is selected from this probe. A permanent pin remains unproven and would require a kernel-level owner mapping beyond this trace.
